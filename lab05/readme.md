## Часть 2: Демонстрация Ping (3 минуты)
### 2.1 Пинг одного хоста
На Linux (192.168.1.20):


sudo python3 ping.py ping 192.168.1.10
Ожидаемый результат:

Результаты пинга:

192.168.1.10         - Ответ от 192.168.1.10 - RTT: 0.52ms

### 2.2 Параллельный пинг нескольких хостов
На Linux (192.168.1.20):


sudo python3 ping.py ping 192.168.1.10 192.168.1.30 8.8.8.8

Ожидаемый результат:

Результаты пинга:

192.168.1.10         - Ответ от 192.168.1.10 - RTT: 0.52ms

192.168.1.30         - Ответ от 192.168.1.30 - RTT: 0.48ms

8.8.8.8              - Ответ от 8.8.8.8 - RTT: 15.23ms

Объяснение: Все хосты пингуются одновременно в отдельных потоках.

## Часть 3: Демонстрация Traceroute (3 минуты)
### 3.1 Traceroute до локального хоста

На Linux (192.168.1.20):


sudo python3 traceroute.py 192.168.1.10

Ожидаемый результат:


Трассировка маршрута до 192.168.1.10

Максимальное количество прыжков: 30

TTL  IP адрес           Время    Статус

 1  192.168.1.10        0.52ms   [REACHED]

Маршрут до 192.168.1.10 найден

## 3.2 Traceroute до интернет-хоста
На Linux (192.168.1.20):

sudo python3 traceroute.py 8.8.8.8

Ожидаемый результат:

Трассировка маршрута до 8.8.8.8

Максимальное количество прыжков: 30

TTL  IP адрес           Время    Статус

 1  192.168.1.1         0.32ms   [TTL expired]

 2  10.0.0.1            1.45ms   [TTL expired]

 3  172.16.0.1          2.78ms   [TTL expired]

 4  192.168.100.1       3.12ms   [TTL expired]

 5  10.10.10.1          5.67ms   [TTL expired]
 ...
 8  8.8.8.8             15.23ms  [REACHED]

Маршрут до 8.8.8.8 найден

Объяснение: Каждый шаг увеличивает TTL на 1. Промежуточные узлы возвращают "TTL expired", конечный узел возвращает "REACHED".

## Часть 4: Демонстрация Smurf-атаки (5 минут)
### 4.1 Подготовка Wireshark
На Windows (192.168.1.10) - жертва:

Запустите Wireshark

Выберите сетевой интерфейс (Wi-Fi или Ethernet)

Установите фильтр: icmp

Нажмите "Start capturing"

## 4.2 Запуск Smurf-атаки
На Linux (192.168.1.20) - атакующий:


 Определите широковещательный адрес

ip addr show | grep broadcast
 Пример: inet 192.168.1.20/24 brd 192.168.1.255 scope global

 Запустите атаку на 5 секунд

sudo python3 ping.py smurf 192.168.1.10 192.168.1.255 10
### 4.3 Что должно быть видно в Wireshark:

No.  Time   Source            Destination       Protocol  Info
1    0.000  192.168.1.10      192.168.1.255     ICMP      Echo (ping) request

2    0.001  192.168.1.20      192.168.1.10      ICMP      Echo (ping) reply

3    0.002  192.168.1.30      192.168.1.10      ICMP      Echo (ping) reply

4    0.003  192.168.1.25      192.168.1.10      ICMP      Echo (ping) reply

5    0.004  192.168.1.15      192.168.1.10      ICMP      Echo (ping) reply


Что показывает атака:

✅ Источник подменен на IP жертвы (192.168.1.10)

✅ Широковещательная рассылка (192.168.1.255)

✅ Все узлы сети отвечают жертве

✅ Множество ICMP ответов приходит на IP жертвы

## Часть 5: Демонстрация последовательного сервера (5 минут)
### 5.1 Запуск сервера

На Linux (192.168.1.20):

sudo python3 server.py

Ожидаемый вывод:

Сервер запущен на 0.0.0.0:9999

Ожидание подключений...

### 5.2 Подключение клиента 1

На Windows (192.168.1.10):

Используйте Telnet или Python

telnet 192.168.1.20 9999

Или через Python:

cmd

python -c "

import socket

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

s.connect(('192.168.1.20', 9999))

print(s.recv(1024).decode())

s.send(b'ping 192.168.1.30\n')

print(s.recv(4096).decode())

s.close()
"

Ожидаемый вывод:

Welcome to ICMP Server

Commands: ping, traceroute, smurf, help, quit

Pinging 192.168.1.30..
.
Результаты пинга:


192.168.1.30         - Ответ от 192.168.1.30 - RTT: 0.48ms

### 5.3 Подключение клиента 2 (пока клиент 1 работает)

На macOS (192.168.1.30):

bash

python3 -c "

import socket

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

s.connect(('192.168.1.20', 9999))

print(s.recv(1024).decode())

s.send(b'traceroute 8.8.8.8\n')

print(s.recv(4096).decode())

s.close()
"
Демонстрация последовательности:

Клиент 2 подключается, пока сервер обрабатывает клиента 1

Сервер обрабатывает клиентов по очереди (последовательно)

Клиент 2 ждет, пока завершится ping клиента 1

Ожидаемый вывод на сервере:

Сервер запущен на 0.0.0.0:9999

Ожидание подключений...

Подключение от 192.168.1.10:54321

Подключение от 192.168.1.30:54322

Отключение от 192.168.1.10:54321

Отключение от 192.168.1.30:54322
